# Full numerical isothermal probes at 0.01 MeV

These are bounded, single-worker local diagnostics from 2026-09-30, not a new cluster sweep.
The production `RMFsolver/phase_velocity.py` is unchanged (SHA-256 `d3d88937d272d62683eb711333d80c405416f1a4dc0fee5c354bd3fc33c49473`).
Physics: automatic maximum interface composition, PNM, massless quarks, and `B_one_forth=189.1565957288247` MeV.
Every reported numerical speed comes from `solve_front_isothermal`, with local diffusion, exact reaction, and finite-flux EOS closures.
The analytical solution with `xi=-0.5` supplies only a current guess; current bounds are one quarter to four times that guess.

## Result

The default initialization found no solution within its budget (five timeouts, one local-EOS exception).
The layer-resolved initialization recovered three distinct full numerical solutions:

| Density / saturation density | Velocity (m/s) | Runtime (s) | Maximum BVP RMS residual |
| --- | ---: | ---: | ---: |
| 3.001 | 74.5351043 | 17.5 | 4.40e-6 |
| 3.01 | 771.9789334 | 22.1 | 3.28e-5 |
| 3.05 | 4139.9647979 | 53.8 | 8.01e-5 |

All three have positive, monotone density profiles, positive currents, endpoint flux errors below `1.8e-15`, and sampled local-EOS residuals below `4.3e-10`.
The tighter check at 3.001 changes its velocity by only `1.08e-10` relatively.
The tighter check at 3.05 timed out at 60 seconds, so that point's mesh/tail independence is **not** established by this experiment.
The improved guesses at 3.1, 3.5, and 5.2 also timed out; 4.5 was only tested with the default initialization.

A logarithmic-temperature plot down to 0.01 MeV is numerically plausible for the existing low-speed contours near the stable-matter boundary, but a robust full-domain calculation is not established.
The next useful work is log-temperature profile continuation with radial refinement near coexistence and accuracy checks, rather than treating these three velocities as a completed contour.
No unresolved velocity has been interpolated or accepted.

## Files and experiments

- `baseline_*.npy`: six calls at density ratios 3.001, 3.01, 3.1, 3.5, 4.5, 5.2, using the production initial mesh/profile. Each has a 40-second hard limit.
- `core_mesh_*.npy`: an initialization-only experiment with a logarithmically resolved physical reaction layer and an approximate positive decay profile. The exact BVP ODE, boundary conditions, and eigenvalue solve remain unchanged. These calls have a 60-second limit.
- `validation_*.npy`: same-state public profile continuation with 450 base nodes, tolerance `1e-5`, and `tail_eps=1e-4`, compared with 300 nodes, `1e-4`, and `1e-3` in the first pass.
- `summary.json` / `summary.csv`: audited results, residuals, and speed changes, generated by `audit.py`.
- `default_*.npy` and `native_bvp_*.npy`: setup failures before any BVP (SciPy import and diagnostic constant-name setup). They are excluded from the physical result table.

Every event and terminal outcome is atomically saved. Timeouts are unresolved numerical trials, not proof of absence of a physical front. Profiles are included only for converged solves.

## Diagnostic initialization

`--core-seed` intercepts only the initial arrays passed into SciPy's BVP solver, in the disposable diagnostic process.
It builds a logarithmic physical-coordinate mesh from a small fraction of the interface decay length to the existing downstream cutoff.
An algebraic-times-exponential density guess and its flux estimate match the interface values and approach the linear downstream tail.
Interpolated thermodynamics appear only in this guess, never in the solved equations.
This is not installed in the public solver and is not yet a validated production initializer for the entire domain.
Because both the initial mesh and profile change, this experiment establishes initialization sensitivity, not the isolated contribution of either change.

## Reproduction

Use a working Python/SciPy environment and a new tag; existing diagnostics are never overwritten:

```bash
python3 probe.py --tag another_test --core-seed --densities 3.001 3.01 3.05 --timeout 60
python3 audit.py
```
